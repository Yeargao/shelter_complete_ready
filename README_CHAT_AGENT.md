# Chatbot Agent 與評估

- 收容所助理使用 `POST /api/agent/chat` 統一路由，原查詢 API 維持相容。管理者可以確認健康、疫苗、驅蟲三類行政欄位及具日期醫療紀錄的修改草案。照護人員不得透過 Agent 修改。
- 每個登入中的對話有伺服器端狀態；清除對話會開啟新對話。未確認草案不寫入資料。日期使用台灣時區，四位 MMDD 預設當年，在草案顯示完整日期。
- 未提供醫療日期時只改行政登錄，不捏造實際施作日期。驅蟲日期更正必須明確輸入「更正驅蟲日期：日期」。疫苗日期新增一般疫苗紀錄；明確更正且僅有一筆一般疫苗紀錄時可更新既有日期；沿用原有 12 個月下次到期規則。實際醫療處置與診斷仍由照護流程負責。
- 同一對話最新可復原的資料修改需再次確認；若有尚未確認草案，「改回來」先取消草案。資料或動物事件已更新時拒絕復原。醫療更正保存修改前後版本至 `ai_medical_corrections`，活動紀錄同步更正，並保存 `ai_action_history`。
- AI 分頁只提供評估。測試使用獨立的 SQLite 記憶體資料庫與固定案例，非正式資料；不使用 Gemini 或變更營運資料。未量測項目顯示未測量。這是小規模回歸測試，不是完整 NLP benchmark。
- 原查詢仍可使用既有 Gemini fallback。新寫入只採明確本機解析及確認，不允許模型直接執行操作；無法辨識時要求補充。

本機測試（在後端環境）：
```sh
cd backend
python -m unittest test_chat_agent test_smart_tools -v
cd ../frontend
npm ci
npm run build
```

## 日常使用
照護人員可查詢本人已完成／待完成任務，並以「回報 動物名稱 完整任務名稱 結果：健康」等方式產生本人任務回報草案；含日期或照片的回報仍使用個人工作台。管理者不能代替員工回報。資料一致性核對首次成功登入後啟動，SQLite 觸發器只將變動的動物加入佇列，首次全量後只核對受影響的資料。相關 API 成功寫入後立即處理佇列；管理者頁面跨帳號更新最遲於下次輪詢顯示。舊的提醒、自動化流程、交接與資源排程核對入口已停用，歷史資料不刪除。
